# n8n expression types

Static types, diagnostics and completions for n8n expressions (`={{ ... }}`), driven by
the TypeScript language service. Two ways to write an expression in code, one plugin
to see everything in the editor.

```sh
pnpm install
pnpm smoke        # build the plugin and drive it against playground/ without an editor
pnpm demo         # service API examples
pnpm typecheck    # root + playground with plain tsc
```

Open the folder in VS Code and accept "Use workspace TypeScript version" (the plugin
only loads with the workspace `typescript`).

TypeScript is pinned to 6.x on purpose. `typescript@7` (latest) is the Go compiler: its npm
package has no `createLanguageService`, no `ts.server`, and no plugin model, only an
`unstable` API. Everything here needs the JS language service, so 6.0.3 is the newest
usable release. VS Code 1.135 bundles 6.0.3 as well; `.vscode/settings.json` keeps the
native preview (`tsgo`) off for this workspace. Then open `playground/strings.ts` and
`playground/lambda.ts`.

## Two forms

**Lambda** (`context.ts`). The expression is TypeScript; the checker types it natively.
No generator involved.

```ts
expression(({ $json, $ }) => $json.n * $('Webhook').item.json.body.orderId, runtime)
// Expression<number>, serialises to "={{ $json.n * $('Webhook').item.json.body.orderId }}"
```

**String** (`resolve.ts`). The expression stays a string. Its type comes from
`N8nResolvedTypes`, a global interface filled per expression by a generator:

```ts
const total = resolve('={{ $input.all().map((i) => i.json.n).sum() }}', runtime); // number
const typo = resolve('={{ $json.test.toUppercase() }}', runtime);
// N8nInvalidExpression<"Property 'toUppercase' does not exist on type 'string'. Did you mean 'toUpperCase'?">
```

The plugin rewrites `<project>/n8n-resolved.d.ts` while you type. `pnpm gen-resolved`
does the same for CI, since `tsc` loads no plugins.

## Files

| File | What |
| --- | --- |
| `service.ts` | `createExpressionService({ ts, root })`: `analyze()` per-block types and errors, `completionsAt()`. Virtual file per expression, tournament shape rules. |
| `globals.ts` | `RuntimeTypes` (sample values) → `RuntimeShape` (type text) → ambient `$json`, `$binary`, `$('Node')`, `$input`, `$parameter`, `$vars` and fixed `$` roots. |
| `shapes.d.ts` | Runtime-independent global shapes (`N8nItem`, `N8nNodeData`, `N8nExecution`, `N8nInvalidExpression`). |
| `extensions.d.ts` | n8n extension methods as global augmentations. Generated by `gen-extensions.ts` from `n8n-workflow` doc metadata. |
| `context.ts` | Lambda form: `ExpressionContext<R>` and `expression()`. |
| `resolve.ts` | String form: `resolve()`, `N8nResolvedTypes`, `n8n` tag. |
| `shape-from-type.ts` | `RuntimeShape` from the checker's type of a `runtime` argument. |
| `scan.ts` | Finds expression literals in a source file; renders `n8n-resolved.d.ts`. |
| `gen-resolved.ts` | CLI generator over a tsconfig. |
| `plugin/` | tsserver plugin: diagnostics, hover, completions, inlay hints, auto-generation. `smoke.ts` runs it headless. |
| `type-level.ts` | Original pure type-level resolver, `$json` paths only. |

## Rules mirrored from n8n

- A value without a leading `=` is a literal string.
- One `{{ }}` block and no surrounding text returns the block's value. Anything else
  concatenates to a string (`@n8n/tournament` `ExpressionBuilder`).
- Each block body is a single JS expression statement.
- Extension methods come from `packages/workflow/src/extensions/*`. Root globals from
  `packages/workflow/src/workflow-data-proxy.ts` and `packages/core/.../get-additional-keys.ts`.

## Known gaps

- Doc metadata types are informal; `any` in the output usually means the doc says `any`.
- `$item()`, `$tool`, `$fromAI()`, `$jmespath()`, `$evaluateExpression()` are `any` by nature.
- Sandbox rules (`constructor`, `__proto__`, bare `$`, class extension) are not enforced.
- Position mapping assumes no escape sequences inside the literal.
- One set of globals. Context-specific sets (credentials, HTTP pagination `$response`/`$pageCount`,
  tool nodes) are not modelled yet.
